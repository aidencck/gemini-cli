# LLM 产生 COT 与优化使用闭环体系（体系化/结构化/分层次）
- 分层架构：数据与训练、提示与解码、运行时推理、输出装配、观测与治理。
- 产生机制：Explicit Prompting（Zero-shot/Few-shot CoT）、SFT/DPO/RLHF、蒸馏/合成、自一致性采样、格式与结构约束。
- 优化策略：提示工程、采样与自一致性、RAG知识增强、工程治理（契约、流式一致、兜底与重试）。
- 工程落地：精选历史与门控判定、 functionCall →调度→统一 functionResponse 、 thought: true 的COT隔离、结构化装配、令牌阈值压缩与上下文重建。
- 质量与治理：判定命中率、工具成功率、COT过滤正确率、装配错误率、成本与压缩频率；单测/集成/契约测试；隐私与审计。
- 闭环时序：非流式与流式两套一致路径，保证解析/过滤/写入的幂等与复现。
- 路线图：训练协同与灰度评估、策略引擎与AB、可视化控制台、企业级SLA与合规。
- 参考与索引：COT端到端闭环、意图识别与COT处理体系、判定机制综述、项目架构深度综述等文档的交叉链接。


本文件系统化梳理「大语言模型（LLM）如何产生思维链（Chain-of-Thought, COT）」「如何提升与优化」「如何在工程中使用」的闭环能力，并结合本项目的落地实践，给出分层架构、关键流程、质量与治理建议。

## 一、执行摘要
- 能力闭环：提示与训练 → 运行时推理 → COT结构化处理 → 质量度量与治理 → 策略迭代与优化。
- 项目定位：本仓库聚焦运行时（意图识别、COT识别与隔离、工具调度、结构化装配、历史维护与压缩、流式/非流式一致性）；训练/微调能力以外部集成为主。
- 目标效果：在复杂任务中提升可解释与稳定推理；在工程层保证可控、可测、可运营、可迭代。

## 二、分层架构与边界
- 数据与训练层（外部能力）
  - 目的：通过 SFT/DPO/RLHF/蒸馏与合成数据等方式，让模型更稳定地产生高质量 COT。
  - 关系：不在本仓库实现；通过模型能力评估与提示策略对接。
- 提示与解码层（Prompt & Decoding）
  - 提示策略：Zero-shot CoT、Few-shot CoT、明确“逐步推理/分步解释”指令、结构化返回约束。
  - 解码控制：温度/采样（Top-p/Top-k）、长度/停止符、段落与标记分割（便于工程解析）。
- 运行时推理层（Runtime Orchestration）
  - 意图门控：精选历史 + 判定提示返回标准 JSON（谁说话/是否继续工具/是否需要解释）。
  - COT识别：识别首段 `thought: true` 部分并隔离处理，避免污染展示与工具输入。
  - 工具协同：`functionCall` → 调度执行 → 统一 `functionResponse` 回写历史。
  - 历史维护：综合历史与精选历史双轨；令牌阈值触发压缩与上下文重建。
- 输出装配层（Assembly & Delivery）
  - 结构化输出：统一“文本+JSON工具调用/响应”；保障 CLI/文档/API 的一致消费体验。
  - 流式一致性：在最终片段统一解析/过滤/写入，保证非流式与流式的一致逻辑。
- 观测与治理层（Observability & Governance）
  - 指标：判定命中率、工具成功率、COT过滤正确率、装配错误率、时延与成本。
  - 安全与隐私：最小披露、脱敏与权限、敏感操作审计；错误分级与告警。

## 三、LLM 如何产生 COT（机理与方法）
- 明确的提示（Explicit Prompting）
  - Zero-shot CoT：在问题中直接添加“请逐步推理/展示思考过程”指令，触发模型输出思维链。
  - Few-shot CoT：提供带推理示例的样例，使模型模仿“步骤化解释”的格式与风格。
- 训练与偏好优化（Training & Alignment）
  - 监督微调（SFT）：用带标注的 COT 数据微调，提升产生 COT 的稳定性与质量。
  - 偏好优化（DPO/RLHF）：对偏好“正确且可解释”的响应打分与优化，强化可靠推理。
  - 蒸馏与合成：从更强模型或策略生成 COT 样本，再蒸馏到目标模型。
- 解码与采样（Decoding & Sampling）
  - 调整温度与采样策略控制探索度；通过停止符与段落结构约束输出格式。
  - 自一致性（Self-Consistency）：多次采样独立推理，聚合答案提升鲁棒性与准确度。
- 结构与格式（Structure & Format）
  - 采用结构化分段（思考/结论/调用），便于工程解析与后续处理。
  - 在本项目中，通过 `parts` 中的 `thought: true` 标记，将“思维链”与“可展示文本/工具结构”区分。

## 四、如何提升与优化（策略与实践）
- 提示工程（Prompt Engineering）
  - 明确“逐步推理/分步解释/先思考再回答”的指令与格式约束。
  - 在复杂任务中引入 Few-shot 示范，统一推理风格与结构。
  - 引导输出“思考→工具调用→结论”分段，降低解析复杂度。
- 采样与自一致性（Sampling & Self-Consistency）
  - 对高难任务采用多样本采样与投票/聚合，提高正确率与稳定性。
  - 在成本约束下动态启用，结合问题难度与历史表现。
- RAG 与外部知识（Knowledge Augmentation）
  - 将检索/知识注入“精选历史”，让模型推理前具备更充分的事实基础。
  - 对专业/长文档场景可使用局部 CoT（例如关注相关片段后再推理）。
- 工程治理（Engineering Governance）
  - 统一结构化输出契约，减少消费端的回归与解析错误。
  - 流式/非流式一致的解析、过滤、历史写入，保障幂等与可复现。
  - 错误兜底与重试策略（判定失败、工具异常、结构不合法）。

## 五、如何在工程中使用（本项目落地）
- 判定与协同
  - 下一说话人：精选历史 + 判定提示，返回标准 JSON（`next_speaker` 与 `reasoning`）。
  - 工具意图：模型声明 `functionCall`，本地解析与调度；`convertToFunctionResponse` 标准化回写。
  - COT隔离：识别 `thought: true` 首段，避免将“内部推理”泄露到用户界面或工具输入。
- 输出与一致性
  - 结构化装配：统一“文本 + JSON”；MCP 响应做内容提取与 JSON 化展示。
  - 流式闭环：在最后片段合并处统一触发解析/过滤/写入，保证与非流式一致。
- 历史与压缩
  - 双轨历史：综合历史（完整）与精选历史（判定上下文）；在令牌阈值处进行压缩与重建。
- 策略与配置
  - 策略开关：仅本地判定/本地优先+模型兜底/模型优先；COT显示/隔离开关；工具自动执行开关。

## 六、质量度量与治理（KPI/测试/隐私）
- 指标体系
  - 判定：命中率、兜底触发率、判定时延。
  - 工具：成功率/失败率/取消率、平均执行时长、重试次数。
  - 输出：结构化装配错误率、COT过滤正确率、流式落盘一致性。
  - 成本：令牌用量、压缩频率、调用次数与费用估算。
- 测试与保障
  - 单测：意图门控、函数响应转译、结构化装配、COT识别分支。
  - 集成：多回合与工具闭环；流式/非流式一致性；压缩触发与上下文重建。
  - 契约/快照：固定输出格式与工具响应结构，防止消费端回归。
- 隐私与合规
  - 最小化披露与脱敏；敏感工具权限与审计；错误分级与告警。

## 七、闭环时序（文本版）
- 非流式：用户输入 → 模型生成（含 COT） → 抽取函数调用/文本 → 工具调度与结果转译 → COT过滤/结构化装配 → 历史记录（精选/综合） → 判定下一说话人 → 续写或等待。
- 流式：用户输入 → 模型流式生成（增量片段，含 COT） → 最末片段合并 → 同步抽取/过滤/装配 → 历史记录 → 下一说话人判定。

## 八、路线图与扩展
- 训练协同：引入带 COT 的 SFT/自一致性策略成果，建立评估与灰度上线机制。
- 策略引擎：规则/概率/成本约束可配置，支持 AB 与在线调参。
- 可视化：判定、工具、装配与历史的时序/状态图；策略控制台（阈值、提示模板、压缩策略）。
- 企业级：SLA 与告警、细粒度权限、数据主权与合规部署。
