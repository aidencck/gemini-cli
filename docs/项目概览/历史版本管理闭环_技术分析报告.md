# 历史版本管理闭环_技术分析报告

本文系统化梳理当前项目的历史版本管理（Conversation/Project 双维度）闭环逻辑：触发 → 快照/检查点保存 → 恢复/回滚 → 会话与工具重调度 → 收敛。覆盖数据对象、存储结构、关键模块、工作流、错误处理与测试覆盖，并提出改进建议。

## 一、范围与目标
- 范围：CLI 与 Core 层围绕会话历史（Chat）与项目文件（Project）的版本管理能力，包括检查点创建、列表、恢复、工具重调度、文件回滚。
- 目标：
  - 明确所有触发点与数据流向，保证“可恢复、可重放、可回滚”。
  - 清楚存储落盘位置与结构，定位问题与支持审计。
  - 为后续演进（一致性、校验、压缩、遥测）提供依据。

## 二、术语与核心数据对象
- 会话检查点（Chat Checkpoint）：由 `Logger.saveCheckpoint` 持久化的对话历史（`Content[]`），用于 `/chat resume|restore|load`。
- 可恢复工具调用（Restorable Tool Call）：在工具请求进入 `awaiting_approval` 状态时，自动保存“快照描述文件 + 项目 Git 阴影快照”，用于 `/restore` 回放。
- 项目阴影仓库（Shadow Git Repository）：位于用户家目录下 `.gemini/history/<project-hash>/` 的隐形 Git 仓库，用于对工作树进行“干净、隔离”的快照与恢复。

### 关键 JSON 结构
- 会话检查点文件（默认或带 `tag`）：`~/.gemini/tmp/<hash>/checkpoint.json` 或 `checkpoint-<tag>.json`，内容为 `Content[]`。
- 可恢复工具调用描述文件：`~/.gemini/tmp/<hash>/checkpoints/<timestamp>-<fileName>-<toolName>.json`，内容示例：
```json
{
  "history": [ /* CLI UI 历史项，供界面恢复 */ ],
  "clientHistory": [ /* GeminiClient 的 Chat 历史（Content[]）*/ ],
  "toolCall": { "name": "replace", "args": { "file_path": "/abs/path", /* ... */ } },
  "commitHash": "<shadow-repo-commit-hash>",
  "filePath": "/abs/path/to/file"
}
```

## 三、存储结构与路径规划
- 项目临时目录：`~/.gemini/tmp/<project-hash>/`（`getProjectTempDir`）。
  - 会话日志：`logs.json`
  - 会话检查点：`checkpoint.json`、`checkpoint-<tag>.json`
  - 可恢复工具调用目录：`checkpoints/*.json`
- 阴影 Git 仓库：`~/.gemini/history/<project-hash>/.git`（工作树指向真实项目根），隔离用户 Git 配置。

## 四、关键模块与职责

### 1) Logger（Core 层）
- 文件：`packages/core/src/core/logger.ts`
- 能力：
  - `initialize()`：基于 `getProjectTempDir()` 初始化 `.gemini/tmp/<hash>/logs.json`、`checkpoint.json`。
  - `saveCheckpoint(conversation: Content[], tag?: string)`：写入默认或带 `tag` 的检查点文件（JSON 数组）。
  - `loadCheckpoint(tag?: string)`：读取检查点文件，返回 `Content[]`，异常与不存在时返回空数组。
  - `_checkpointPath(tag)`：生成 `checkpoint[-tag].json` 路径。
  - JSON 容错：遇到不合法 JSON 或非数组会备份 `.bak` 并重置为空数组。

### 2) GitService（Core 层）
- 文件：`packages/core/src/services/gitService.ts`
- 能力：
  - `initialize()`：校验项目是否 Git 仓库与本机是否安装 Git，随后 `setupShadowGitRepository()`。
  - `setupShadowGitRepository()`：
    - 历史目录：`~/.gemini/history/<hash>/`，建立独立 `HOME/XDG_CONFIG_HOME`，写入 `.gitconfig` 强制 `user/email` 与禁用 `gpgsign`。
    - 初始化阴影仓库并做空提交；复制项目 `.gitignore` 到阴影仓库，保证忽略规则一致。
  - `createFileSnapshot(message)`：`git add .` + `git commit`，返回 `commit` 哈希。
  - `getCurrentCommitHash()`：读取 `HEAD` 哈希。
  - `restoreProjectFromSnapshot(commitHash)`：`git restore --source <hash> .` + `git clean -fd` 清理未追踪文件。

### 3) useGeminiStream（CLI 层）自动保存可恢复工具调用
- 文件：`packages/cli/src/ui/hooks/useGeminiStream.ts`
- 逻辑：`saveRestorableToolCalls()` 在依赖变更（`toolCalls`）时：
  - 前置：`config.getCheckpointingEnabled()` 打开、工具为 `replace|write_file` 且 `status === 'awaiting_approval'`。
  - 动作：
    - 建立 `~/.gemini/tmp/<hash>/checkpoints/` 目录（忽略已存在）。
    - 使用 `GitService.createFileSnapshot()` 创建快照，若失败尝试 `getCurrentCommitHash()`；若仍失败则跳过该工具调用。
    - 写入描述文件：包含 `history`（当前 CLI UI 历史）、`clientHistory`（GeminiClient 历史）、`toolCall`（名称与参数）、`commitHash`、`filePath`。

### 4) Slash Commands（CLI 层）
- 文件：`packages/cli/src/ui/hooks/slashCommandProcessor.ts`
- `/chat`：
  - `save`：调用 `Logger.saveCheckpoint(chat.getHistory(), tag?)`，提示保存成功或空会话。
  - `resume|restore|load`：`Logger.loadCheckpoint(tag?)` → 清空 UI 历史与 Chat 历史 → 将 `Content[]` 映射为 UI 项（跳过系统提示或非文本 Part），恢复屏幕显示。
  - `list`（通过 `savedChatTags()`）：枚举 `~/.gemini/tmp/<hash>/checkpoint-*.json` 返回 tag 列表。
- `/restore`（当 `config.getCheckpointingEnabled()` 为真时可用）：
  - 自动补全：列出 `~/.gemini/tmp/<hash>/checkpoints/*.json` 文件名（去掉 `.json`）。
  - 恢复流程：
    - 读取选定描述文件，若存在 `history` → `loadHistory` 恢复 UI 历史；若存在 `clientHistory` → `GeminiClient.setHistory` 恢复 Chat。
    - 存在 `commitHash` → `GitService.restoreProjectFromSnapshot(hash)` 回滚项目工作树；提示回滚完成。
    - 返回 `{ shouldScheduleTool: true, toolName, toolArgs }` → 由管线重新调度对应工具调用，闭环继续。

## 五、闭环工作流（从触发到收敛）
1) 触发保存：
   - 自动：工具调用进入 `awaiting_approval`（`replace|write_file`），保存“可恢复工具调用描述”+ 阴影仓库快照。
   - 手动：用户 `/chat save [tag]` 保存会话检查点。
2) 列表/选择：
   - Chat：`/chat list`（隐含调用 `savedChatTags()`）。
   - Tool：`/restore` 自动补全列出 `checkpoints/*.json`。
3) 恢复/回滚：
   - Chat：`/chat resume|restore|load [tag]`，加载 `Content[]` → 清屏并重建 UI 历史与 Chat 内存。
   - Project：`/restore` 根据 `commitHash` 回滚文件树。
4) 重调度：
   - `/restore` 返回 `shouldScheduleTool`，由上层调度器继续执行建议工具调用，实现“恢复后继续执行”的闭环。
5) 收敛：
   - 用户看到恢复后的上下文与文件状态，确认或调整后继续工作；必要时再次生成快照与检查点。

## 六、错误与异常处理
- 目录/文件：
  - 创建 `checkpoints/` 目录时忽略 `EEXIST`；其他错误写入调试消息并停止保存。
  - 检查点读取：`ENOENT` → 返回空数组；非法 JSON → 记录错误并返回空数组；非数组 → 警告并返回空数组。
- 快照：
  - `createFileSnapshot()` 失败时尝试 `getCurrentCommitHash()`；两者都失败则跳过该工具调用保存。
- 参数校验：
  - 工具请求缺失 `file_path` 则跳过保存并写入调试消息。
- 环境校验：
  - `GitService.initialize()` 需项目处于 Git 仓库且系统安装 Git，不满足则抛错（在调用处需要前置保障）。

## 八、安全与隔离设计
- 阴影仓库环境变量：`GIT_DIR`、`GIT_WORK_TREE`、`HOME`、`XDG_CONFIG_HOME` 指向历史目录，避免污染用户全局配置。
- 禁用 GPG 签名、固定 `user/email`，确保提交可重现且无外部副作用。
- 尊重项目 `.gitignore`：阴影仓库复制忽略规则，避免非预期内容进入快照。

## 九、改进建议
- 统一与增强数据契约：
  - 为可恢复工具调用 JSON 与会话检查点文件定义 JSON Schema，并在读写时进行校验（版本号、必填字段、类型约束）。
  - 在工具描述文件中追加 `toolCallId`、`displayTitle`、`resultSchemaVersion`，方便列表与前向兼容。
- 原子写入与校验：
  - 写入使用临时文件 + 原子重命名策略，减少部分写入导致的损坏风险。
- 命名与目录策略：
  - 将会话检查点与工具快照目录对齐命名（如 `chat-checkpoints/` 与 `tool-checkpoints/`），并在 `/chat list` 显式区分。
- 恢复策略优化：
  - `/restore` 支持“只恢复项目”或“只恢复会话”的细粒度选项；支持预览 diff。
- 遥测与审计：
  - 记录恢复与回滚事件（含哈希与文件数）到遥测日志，辅以隐私保护策略。
- 压缩与清理：
  - 对大型 `clientHistory` 进行语义压缩（保留关键摘要）；提供 `cleanup` 策略（TTL/数量上限）。

## 十、使用示例与运维
- 保存会话检查点：
  - 输入命令：`/chat save my-tag`
  - 生成文件：`~/.gemini/tmp/<hash>/checkpoint-my-tag.json`
- 列出会话检查点标签：
  - 输入命令：`/chat list`
- 恢复会话：
  - 输入命令：`/chat resume my-tag`
  - 效果：清空当前历史，恢复 UI 与 Chat 历史。
- 自动保存可恢复工具调用：
  - 当工具为 `replace|write_file` 且状态 `awaiting_approval`，系统自动生成 `checkpoints/*.json` 与项目阴影快照。
- 回放并回滚项目：
  - 输入命令：`/restore`
  - 从列表选择条目后：恢复 UI/Chat 历史，回滚文件到对应 `commitHash`，并重新调度工具调用。
