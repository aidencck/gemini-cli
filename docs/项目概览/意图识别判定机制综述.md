# 意图识别判定机制综述（本地规则与模型协同）

本文将“项目中的意图识别究竟在本地完成还是交由模型识别”的讨论整理为一份结构化文档，明确结论、方法与落地建议，便于后续架构演进与治理。

## 核心结论
- 采用混合式意图识别：
  - 本地执行轻量级规则判定与结构修复（安全兜底）。
  - 将精选历史提交给模型进行“下一说话人”的主要判定，返回标准化 JSON 结论。
  - 工具意图由模型显式声明（函数调用），项目侧本地解析并调度执行。

## 本地判定与结构修复
- 函数响应末条判定：当末条为用户的纯函数响应，直接判定由“模型”继续（解释/续写/总结）。
- 空模型消息兜底：末条为模型且内容为空时，注入空文本以形成合法结构，避免服务端拒绝，并继续由模型发言。
- 思维链隔离：识别“思维链”标记的内部推理段，在输出装配时进行过滤或分离，确保对用户展示与工具输入不被污染。
- 工具调用识别：从响应中抽取函数调用声明，如存在则进入工具调度并将结果统一转译为函数响应回写历史。

## 模型驱动的意图识别
- 下一说话人决策：以精选历史为上下文，追加判定提示，调用模型生成符合约定模式的 JSON 结果（包含“user/model”与简要理由）。
- 异常与回退：当模型判定失败或异常返回时，保持流程不强推进，结合本地兜底规则避免对话僵停。

## 工具意图的来源与落地
- 来源：模型在响应中显式声明函数调用（工具意图）。
- 落地：项目侧解析函数调用并交由调度器执行；将结果规范化转译为函数响应并写回历史，以支撑后续推理与展示。

## 时序与一致性
- 非流式：在生成完成后统一解析、判定与历史写入。
- 流式：在最后片段合并处执行同样的解析与写入，保持跨模式一致的时序与幂等性。

## 为什么采用混合式
- 可靠性：本地规则提供安全兜底，避免非法结构与边界错误传播；模型判定处理复杂语义与模糊意图。
- 成本与体验：仅在必要场景调用模型做判定，其余走本地快路径；平衡准确率与调用成本。

## 配置与策略建议
- 强化本地规则：扩展更多可本地判定的模式（如“明确承诺下一步动作”的检测），减少模型判定频次。
- 优化判定提示与模式：根据业务风格微调判定提示与返回模式，提升“未完成输出/继续执行”的识别稳定性。
- 策略开关：引入三种策略模式以适配不同成本与准确需求：
  - 仅本地规则（最省成本，但语义复杂度受限）。
  - 本地优先 + 模型兜底（通用推荐）。
  - 模型优先（最优语义准确性，成本较高）。

## 落地与治理建议
- 监控与度量：对判定耗时、命中率、错误率与成本进行遥测，以数据驱动策略优化。
- 安全与隐私：对工具参数与返回值最小化披露，必要时进行脱敏与权限控制。
- 回归与一致性：通过契约/快照测试固定判定与装配输出格式，避免改变影响消费端。
