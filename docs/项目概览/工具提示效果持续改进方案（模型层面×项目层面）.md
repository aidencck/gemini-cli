# 工具提示效果持续改进方案（模型层面 × 项目层面）

目标：让模型在COT阶段稳定、明确、可执行地指导工具使用，提升端到端成功率与工程复用性。面向当前项目，提出从模型与项目两层的系统化改进方案，明确关键提示内容与具体执行步骤。

## 0. 现状诊断（结合本项目）
- 文档已具备：`COT返回数据处理与工程实现.md`、`COT阶段工具指导与步骤规划.md`、`COT数据集构建方法论.md` 等，具备合同与处理框架。
- 待加强：
  - 模型端对“先工具计划后思维链”的强约束与一致风格
  - 统一 `tool_plan` 校验与自动门控的落地细则与度量
  - 数据集内工具相关样本的配额、难度递进与长尾补齐

## 1. 模型层面改进
- 提示工程（Prompt）
  - 强约束输出结构：统一合同（`cot_thought.thought=true` 与 `tool_plan` 并置、`when/expect/rollback/auto_execute`）
  - Few-shot模板：覆盖 Bug修复/新功能/重构/测试/评审 等任务，强调“先列工具与步骤，再展开推理”
  - 风格控制：原子化短句、可验证证据、引用源路径与行；禁止夸饰与无依据猜测
- 训练数据（COT Dataset）
  - 分层抽样：任务类型×领域×技能×难度×风格；提升工具相关场景占比（≥30%）
  - 正/负样本：正确工具链 vs 错误工具选择/顺序/门控；用于DPO
  - 奖励信号：工具成功率、编译/测试通过率、合同合规，融入RLHF
- 推理策略（Inference）
  - 动态启停：复杂任务启用完整COT与工具链，简单任务压缩COT并禁用工具
  - 自一致性与剪枝：生成多路工具计划，投票保留一致方案，删除冗余

## 2. 项目层面改进
- 合同与门控
  - `tool_plan` JSON Schema 落盘与校验；在 `ci.yml` 增加静态检查
  - 门控策略：检查 `when` 条件、幂等与安全；违规则中止并给出人审钩子
- 执行与回放
  - 执行序列：按依赖与风险排序；失败触发 `rollback` 并记录
  - 回放机制：日志与补丁可重跑；输出结构化执行报告
- 度量与反馈
  - 指标：合同合规率、工具执行成功率、回退触发率、端到端成功率、平均token与耗时
  - 闭环：将失败案例回流至数据集与Prompt模板，定向增补与改写

## 3. 关键提示内容（面向提示工程）
- 明确角色与目标：你是代码助手，先计划工具再进行思维链
- 输出合同：
  - `cot_thought.thought=true`，列出 step_1..n（目的/输入/成功判定/风险/引用）
  - `tool_plan.tools=[{name,args,when,expect,rollback}]`，`auto_execute=false`
- 门控声明：只有满足 `when` 和安全策略的步骤才执行；失败按 `rollback` 退回
- 引用要求：涉及代码或日志必须提供路径与行号；不允许泛泛而谈
- 成本与风格：短句、原子步；限制 token；禁止无依据猜测

## 4. 具体执行步骤（项目集成）
1) 落盘 Schema 与校验脚本：
   - `schema/tool_plan.schema.json`（定义字段与约束）
   - `scripts/validate_tool_plan.js`（JSON 校验 + 静态门控检查）
2) 集成到 CI：
   - 在 `.github/workflows/ci.yml` 中新增校验步骤：`node scripts/validate_tool_plan.js` 批量检查样本/日志
3) 提示模板落地：
   - 在 `docs/项目概览/COT阶段工具指导与步骤规划.md` 补充 Few-shot 模板与字段解释
4) 数据集迭代：
   - 在 `COT数据集构建方法论.md` 定义工具相关样本配额（≥30%），按难度 L0→L4 递进
   - 构造 DPO 正负对：错误工具选择、错序、缺失 `when`/`rollback`
5) 指标与反馈：
   - 增加脚本收集执行指标，按批次生成报告，落盘到 `docs/CI/`
