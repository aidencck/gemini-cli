# 工程总搜索功能：全链路闭环流程技术说明

## 文档目标与适用范围
- 系统化整理“工程总搜索”在项目中的端到端闭环流程，面向技术专家与工程团队。
- 从战略、战术、操作、支撑四层说明设计、实现、监控与持续改进，映射到现有目录与工具。

## 闭环总览（从查询到收敛）
1. 查询输入与意图识别：用户输入关键词/符号/路径/模式，解析意图与范围。
2. 搜索计划生成：选择策略（正则/文本/语义/AST），制定执行步骤与并发度、超时、过滤器。
3. 执行与流式反馈：逐步扫描与索引检索，去重与排序，流式返回命中结果与上下文片段。
4. 交互与后续动作：用户打开命中文件/跳转位置、二次过滤、追加查询或保存搜索。
5. 质量门控与度量：延迟、召回、误报率、错误率、取消率、资源占用统计与阈值门禁。
6. 异常与恢复：权限/二进制文件/大仓库/路径遍历等异常分类与回退策略。
7. 历史维护与优化：查询历史、常用模板、缓存策略与索引增量更新，持续调优。

## 分层架构与项目映射
- 战略层（目标与标准）
  - 能力目标：跨仓库/多语言检索、低延迟（P95 < 2s）、高召回、可观测与可审计。
  - 质量标准：门禁阈值、误报/漏报控制、资源上限与安全合规要求。
  - 文档映射：`docs/index.md`、`docs/项目概览/00.00_项目架构深度综述.md`、CI 配置（`.github/workflows/ci.yml`）。
- 战术层（策略与编排）
  - 策略路由：正则检索（ripgrep）、全文检索、语义检索（嵌入）、AST/符号级检索的组合与优先级。
  - 计划生成：并发分片、路径/类型过滤、采样与分页、流式返回、降级链与重试策略。
  - 文档/工具映射：`docs/cli/commands.md`、`docs/core/tools-api.md`、`docs/tools/index.md`、`docs/implementation-guide.md`。
- 操作层（执行与反馈）
  - 执行组件：本地扫描器（ripgrep）、索引器（文件树/符号/嵌入）、结果合并与排序器、流式响应桥接。
  - 接口契约：统一请求/响应结构，支持流式与取消、错误格式化与审计。
  - 文档/目录映射：`packages/cli/`（命令与输出）、`packages/core/`（服务与契约）、`integration-tests/`（覆盖与基线）。
- 支撑层（安全/异常/度量/历史）
  - 安全与合规：路径白名单、二进制/大文件处理、权限校验、路径遍历防护。
  - 异常处理：环境错误分类、回退与提示、审计记录与重现信息。
  - 度量与历史：`docs/telemetry.md`、`scripts/telemetry*.js`，查询历史与缓存策略；`历史对话维护体系.md` 的压缩思路可复用在历史搜索摘要。

## 数据契约与类型定义（建议）
```ts
export interface SearchRequest {
  query: string;                 // 原始查询（关键词/正则/符号）
  mode: 'regex' | 'text' | 'semantic' | 'symbol';
  includes?: string[];           // 目录或文件类型白名单
  excludes?: string[];           // 黑名单（如 node_modules、dist）
  maxResults?: number;           // 结果上限
  timeoutMs?: number;            // 超时
  stream?: boolean;              // 是否流式返回
  semantic?: {                   // 语义检索参数
    embeddingModel?: string;
    topK?: number;
    minScore?: number;
  };
}

export interface SearchHit {
  file: string;                  // 文件相对路径
  line: number;                  // 命中行
  snippet: string;               // 片段（命中上下文）
  symbol?: string;               // 命中的符号/标识符
  score?: number;                // 排序/语义得分
  metadata?: Record<string, any>;// 语言/类型/大小等
}

export interface SearchResult {
  requestId: string;
  hits: SearchHit[];
  total: number;                 // 合并后结果数
  elapsedMs: number;             // 总耗时
  truncated?: boolean;           // 是否截断
  errors?: { file?: string; message: string; }[];
}

export interface SearchPlan {
  steps: Array<{
    type: 'scan' | 'index' | 'semantic' | 'symbol';
    params: Record<string, any>;
    timeoutMs?: number;
    retry?: { maxRetries: number; backoff: 'exponential' | 'linear' };
  }>;
  parallelGroups?: string[][];  // 并行分组
  rollbackPlan?: string[];      // 回退策略
}
```

## 执行流程（可流式）
- 输入解析
  - 识别模式（正则/文本/语义/符号），抽取 include/exclude、文件类型与路径约束。
  - 生成 `SearchPlan` 与并发策略（分片扫描/索引检索）。
- 执行前检查
  - 目录可访问性与白/黑名单生效情况；二进制/大文件过滤；资源配额检查。
- 核心执行
  - 正则/文本扫描：基于 ripgrep 或等效扫描器，开启行号与上下文片段提取。
  - 语义检索：对文件/片段生成或加载嵌入，执行相似度查询（向量索引）；按 `topK`/`minScore` 过滤。
  - 符号检索：解析 AST/符号表（语言感知），命中函数/类/接口等标识符。
  - 结果合并：多通道命中集合，按得分与相关性排序，去重与分页。
- 流式反馈
  - 边执行边返回 `SearchHit`，每批次附带统计与进度。
  - 支持取消（`AbortSignal`）与超时；错误分级回传（环境/路径/权限/解析错误）。
- 后续动作
  - 打开文件并跳转到命中行；支持追加查询/过滤；保存搜索模板与历史。
- 收敛与沉淀
  - 生成执行报告与摘要；记录度量并更新策略（过滤器、并发、缓存）。

## 质量门控与指标（建议）
```yaml
search_quality_gates:
  latency:
    p95: 2000ms
    p99: 5000ms
  recall:
    baseline_corpus_min_recall: 90%
  precision:
    false_positive_rate_max: 5%
  errors:
    error_rate_max: 2%
  resources:
    max_cpu_utilization: 85%
    max_memory_usage_mb: 1024
```

- 指标采集
  - 延迟：`elapsedMs`、分阶段耗时（扫描/索引/合并）。
  - 召回/准确率：基于基准语料与标注集对比（在 `integration-tests/` 中放置测试仓与查询集）。
  - 错误率：环境/权限/解析错误；取消率与超时率。
  - 资源：CPU/内存/IO；并发度与文件数。

## 异常处理与回退
- 路径与权限：拒绝路径遍历；对不可读目录记录并提示；提供替代路径建议。
- 大仓库与二进制：分片扫描与采样；二进制识别与跳过；对超大文件采用摘要式预览。
- 语义索引缺失：回退到正则/文本；异步构建嵌入索引并缓存。
- 解析错误：语言识别失败/AST失败时回退到文本模式并标注降级。
- 取消与超时：清理执行上下文与资源；记录未完成进度用于下次恢复。

## 安全与合规
- 路径白名单与沙箱：限制在工作区内；禁止跨用户目录与敏感系统路径。
- 敏感数据：在预览中脱敏（密钥、凭证），提供安全过滤器选项。
- 审计与留痕：记录查询、范围、结果数量与错误信息，便于复盘与合规检查。

## 性能优化与工程实践
- 缓存：命中缓存与结果缓存；热目录与热门查询缓存。
- 并发与分片：按目录/文件类型分片并行；IO 受限时调度限流。
- 索引：轻量文件树索引与符号表；语义嵌入离线/增量构建。
- 去重与排序：行级/符号级去重；结合语义/位置/频次的综合排序。
- 历史与模板：保存查询模板；对重复查询进行聚合与提示。

## 落地步骤与检查清单
- 需求与目标：明确 P95 延迟、召回率目标与目录范围。
- 命令与接口：在 `packages/cli/` 增加 `search` 命令与流式输出；在 `packages/core/` 提供契约与服务实现。
- 工具与适配：对接扫描器与嵌入模型（详见 `docs/tools/index.md`、`docs/implementation-guide.md`）。
- 测试与门禁：在 `integration-tests/` 构造基准仓与查询集；在 CI 门禁中加入质量阈值。
- 遥测与面板：启用 `scripts/telemetry*.js` 采集指标；在 CLI/IDE 提供“搜索度量面板”。

## 与现有工具的协作
- 扫描搜索：对应“快速正则/文本检索”，可参考 `docs/tools/web-search.md` 与本地 `ripgrep` 集成。
- 代码库检索：与“代码库检索服务”协作（语义/符号级），在核心层统一合并与排序。
- 取消与审批：集成 `AbortSignal` 与关键路径审批（长时间/大范围搜索提示与确认）。

## LLM参与分析（输入→搜索返回）
- 本地代码搜索路径（当前实现）
  - 工具与代码证据：`packages/core/src/tools/grep.ts`（`GrepTool`）。优先使用 `git grep`，回退到文件系统扫描与 `glob`，对命中行进行聚合与排序，构造返回字符串。
  - 结论：不调用 LLM 进行检索或生成内容。返回中的 `llmContent` 字段仅为工具格式化的文本结果，并非模型推理产物。
- 语义/向量检索（当前状态）
  - 代码检索结论：在 `packages/core`/`packages/cli` 未发现嵌入构建、向量索引或相似度查询实现（关键词：`embedding`、`vector`、`semantic`）。相关能力仅在文档层规划（如“RAG技术集成实施方案”）。
  - 结论：当前版本的本地搜索未使用嵌入/向量检索与模型重排。
- AST/符号级检索（当前状态）
  - 代码检索结论：未发现多语言 AST 解析或符号表构建的落地代码，属规划方向。
  - 结论：当前版本的符号/AST检索未落地，未涉及 LLM。
- 网络搜索路径（区分说明）
  - 工具与代码证据：`packages/core/src/tools/web-search.ts`（`WebSearchTool`）。通过 Gemini API 的 `googleSearch` 工具执行网络搜索并返回总结，属于外部信息检索与生成，与本地代码搜索链路不同。
  - 结论：网络搜索使用 LLM 能力进行摘要与引用，但不参与本地代码搜索结果的生成。
- 综述与架构映射
  - 输入→本地搜索返回：`CLI` → `Core ToolRegistry` → `GrepTool` → 结果合并与格式化 → 返回。此链路不依赖 LLM。
  - 输入→网络搜索返回：`CLI` → `Core` → `WebSearchTool` → Gemini API → 返回。此链路存在 LLM 参与，但与工程“本地代码搜索”解耦。

### 结论与建议
- 结论：当前项目版本中，从“用户输入到本地搜索返回”的闭环不使用 LLM；LLM 仅用于网络搜索与内容处理（如 `web-fetch` 的页面内容摘要），与本地代码搜索分离。
- 建议：
  - 在配置中明确默认搜索模式为非 LLM（如 `search.defaults.mode: regex`），并将语义/向量方案作为可选扩展模块。
  - 若需引入混合检索与模型重排，建议新增 `packages/core/src/services/search/hybridSearchService.ts`，外置嵌入索引与向量库，并在 `TaskPlan` 中加入“搜索策略”与“门控阈值”。
  - 在 CLI 提供“搜索策略开关”和“LLM参与提示”，确保用户可感知并控制何时启用模型能力。
