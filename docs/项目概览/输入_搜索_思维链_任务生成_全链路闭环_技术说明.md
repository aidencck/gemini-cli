# 输入-搜索-思维链-任务生成：全链路闭环技术说明

## 文档目标与适用范围
- 系统化、分层次整理从“用户输入”到“任务生成”的端到端闭环实现逻辑，指导工程落地、质量控制与持续改进。
- 面向技术专家与工程团队，映射到现有 CLI、Core、Tools、Model、CI、Telemetry 等模块与文档。

## 闭环总览（从输入到收敛）
1. 用户输入与意图识别：解析输入类型（命令/自然语言/路径/模式）、抽取意图与范围。
2. 搜索关键词生成：从意图与上下文派生关键词/正则/符号/语义嵌入查询，生成搜索计划。
3. 搜索执行与结果合并：多通道执行（正则/全文/语义/符号），合并排序与去重，流式反馈命中片段。
4. 思维链构建（COT）：在阶段化提示与工具返回的约束下，推理工作分解、假设验证与决策记录。
5. 任务生成与编排：将 COT 变为结构化任务列表、约束与依赖，输出执行计划与工具调用契约。
6. 执行与质量门控：工具执行、质量阈值门禁、错误分级与回退、审计记录与可视化度量。
7. 反馈与历史维护：结构化结果汇总、历史压缩与索引、查询模板与策略迭代，形成持续改进闭环。

## 分层架构与项目映射
- 战略层（目标/标准/合规）
  - 目标：高可用闭环（P95 < 2s 搜索延迟、任务生成一轮收敛率 > 80%）、可观测与可审计、可降级。
  - 标准：质量门禁阈值、错误分级与回退策略、资源配额与安全边界。
  - 映射：`docs/index.md`、`docs/项目概览/00.00_项目架构深度综述.md`、CI 工作流（`.github/workflows/ci.yml`）。
- 战术层（策略/计划/路由）
  - 输入路由：命令/自然语言/文件操作三类入口，意图解析与策略切换。
  - 搜索策略：正则/文本/语义/符号组合；并发分片、过滤器与超时、流式与分页。
  - COT 策略：阶段化提示模板、约束式思维链、验证-决策-记录三段式。
  - 任务编排：任务依赖与优先级、工具合约、审批与取消、回退链与重试策略。
  - 映射：`docs/cli/commands.md`、`docs/core/tools-api.md`、`docs/model/prompt核心分析框架.md`、`docs/implementation-guide.md`。
- 操作层（执行/反馈/门控）
  - 执行：搜索器（ripgrep/索引/嵌入/符号）、COT 推理、任务计划器、工具执行器。
  - 反馈：统一请求/响应契约、流式结果、错误分级、取消与超时、审计日志。
  - 门控：质量阈值检查、资源配额、异常分类与回退、度量采集与报告。
  - 映射：`packages/cli/`、`packages/core/`、`integration-tests/`、`scripts/telemetry*.js`。
- 支撑层（安全/异常/度量/历史）
  - 安全：路径白名单/沙箱、数据脱敏、权限校验、路径遍历防护。
  - 异常：环境/权限/超时/解析错误/模型退化，回退与提示、审计可重现。
  - 度量：延迟/召回/误报/错误率/资源；历史与模板、缓存与索引增量更新。
  - 映射：`docs/telemetry.md`、`docs/tools/index.md`、`docs/项目概览/历史对话维护体系.md`。

## 核心数据契约与类型建议
```ts
export interface InputEvent {
  raw: string;                    // 原始输入
  channel: 'cli' | 'chat' | 'file_op';
  context?: { cwd?: string; file?: string; selection?: string };
}

export interface Intent {
  type: 'search' | 'refactor' | 'question' | 'task_gen' | 'open_file';
  confidence: number;
  params?: Record<string, any>;   // includes/excludes、语言、文件类型等
}

export interface KeywordPlan {
  query: string;                  // 关键词/正则/符号名
  mode: 'regex' | 'text' | 'semantic' | 'symbol';
  expansions?: string[];          // 同义/派生词
  filters?: { includes?: string[]; excludes?: string[]; types?: string[] };
}

export interface SearchRequest extends KeywordPlan {
  maxResults?: number;
  timeoutMs?: number;
  stream?: boolean;
  semantic?: { embeddingModel?: string; topK?: number; minScore?: number };
}

export interface SearchHit {
  file: string; line: number; snippet: string; symbol?: string; score?: number;
}
export interface SearchResult {
  requestId: string; hits: SearchHit[]; total: number; elapsedMs: number;
  truncated?: boolean; errors?: { file?: string; message: string; }[];
}

export interface CoTStep {
  id: string; title: string; rationale: string; evidence?: string[]; decision?: string;
}
export interface CoTTrace {
  steps: CoTStep[];              // 阶段化推理链
  constraints?: string[];        // 输入/工具/质量约束
}

export interface TaskSpec {
  title: string; intent: Intent; inputs?: Record<string, any>;
  deps?: string[]; priority?: 'high'|'medium'|'low';
}
export interface TaskPlan {
  tasks: TaskSpec[];             // 结构化任务列表
  toolCalls?: Array<{ name: string; args: Record<string, any>; approval?: boolean }>;
  qualityGates?: Record<string, any>;
}

export interface ExecutionReport {
  requestId: string; status: 'success'|'partial'|'failed';
  summary: string; metrics?: Record<string, number>; errors?: string[];
}
```

## 阶段流程与控制点
- 阶段 1：输入与意图识别
  - 解析通道与上下文；正则/语义/符号模式识别；意图类型与置信度。
  - 控制点：`min_confidence` 阈值、歧义提示与用户确认、路径白名单校验。
- 阶段 2：关键词生成与计划
  - 基于意图和上下文派生关键词、同义词与正则；模式选择与过滤器生成；并发与超时设定。
  - 控制点：`includes/excludes` 基线模板、模式选择优先级、流式与分页策略。
- 阶段 3：搜索执行与合并
  - 多通道并发执行；片段与符号级命中；合并、去重与排序；错误分级与降级回退。
  - 控制点：`maxResults`、`timeoutMs`、语义 `minScore`、行/符号去重阈值。
- 阶段 4：思维链构建（COT）
  - 结构化提示：阶段标题、理由、证据、决策；与工具返回对齐；约束驱动推理。
  - 控制点：COT 隔离（不泄露实现细节）、阶段门控（必须有证据与决策）、长度与压缩策略。
- 阶段 5：任务生成与编排
  - 将 COT 步骤映射为 `TaskSpec`；依赖与优先级；工具合约与审批；质量门禁绑定。
  - 控制点：任务阈值（最多 N 项）、审批提示（高风险工具）、回退链与重试策略。
- 阶段 6：执行与质量门控
  - 工具执行、流式反馈、取消与超时；门控检查（延迟/召回/误报/错误率/资源）。
  - 控制点：CI 门禁阈值、错误分级（环境/权限/解析/模型）、资源配额与限流。
- 阶段 7：反馈与历史维护
  - 结构化报告与摘要；查询与任务历史；缓存与索引增量更新；策略迭代。
  - 控制点：审计日志字段、历史压缩规则、模板推荐与个性化提示。

## 提示工程与 COT 机制
- 阶段模板（全量格式）：固定结构 输入→意图→证据→决策→任务，避免自由文本漂移。

### 阶段模板全量格式（定义与约束）

- 核心结构：`输入 → 意图 → 证据 → 决策 → 任务`
- 设计原则：
  - 所有决策必须绑定至少一个证据（命中或上下文）。
  - 意图必须提供类型与置信度，并给出策略理由。
  - 任务列表对齐工具契约与审批模式（非 YOLO 模式下禁止写操作）。
  - 可审计：每个字段均可落日志并复盘。

```ts
export interface StageTemplate {
  stageId: string;              // 阶段唯一ID（如 S-001）
  title: string;                // 阶段标题（如：解析输入与范围）
  input: InputSpec;             // 输入规范
  intent: IntentSpec;           // 意图判定
  evidence: EvidenceSpec[];     // 证据列表（命中/上下文）
  decision: DecisionSpec;       // 决策（绑定证据）
  tasks: TaskSpec[];            // 任务列表（复用本文件定义的 TaskSpec）
}

export interface InputSpec {
  raw: string;                  // 原始输入文本
  parsed?: {
    mode?: 'regex'|'text'|'semantic'|'symbol';
    includes?: string[];
    excludes?: string[];
    timeoutMs?: number;
    stream?: boolean;
  };
  assumptions?: string[];       // 前提假设/约束
  context?: { cwd?: string; repo?: string; files?: number };
}

export interface IntentSpec {
  type: 'search'|'edit'|'refactor'|'run'|'question';
  confidence: number;           // 0.0 ~ 1.0；默认门槛 `min_confidence`
  rationale?: string;           // 判定理由（简要）
  strategy?: string[];          // 计划使用的工具/策略（如 grep、glob、read-file）
}

export interface EvidenceSpec {
  source: 'grep'|'glob'|'read-file'|'context'|'web';
  ref: string;                  // 证据引用ID（如 hit-1）
  file?: string;                // 文件路径（相对）
  line?: number;                // 命中行
  snippet?: string;             // 片段
  symbol?: string;              // 命中符号
  score?: number;               // 相关性/语义得分（如有）
}

export interface DecisionSpec {
  statement: string;            // 决策陈述
  justification: string[];      // 证据引用（ref:hit-*）与理由
  risks?: string[];             // 风险列表
  qualityGates?: {              // 阶段级质量门控
    minConfidence?: number;     // 意图置信度下限（默认 0.6）
    maxLatencyMs?: number;      // 阶段最大延迟
  };
}
```

约束与校验（建议）：
- 置信度门槛：`intent.confidence >= input.min_confidence`，否则触发歧义提示或回退。
- 证据绑定：`decision.justification` 至少包含一个有效 `evidence.ref`。
- 写操作工具：当 `ApprovalMode !== YOLO` 时，任务中 `EditTool/WriteFileTool/ShellTool` 需显式审批或被过滤。
- 超时与取消：遵循 `timeoutMs` 与 `AbortSignal`；长时阶段需提示与确认。

- 约束提示：工具参数契约、质量阈值、资源配额在提示中显式声明。
- 证据绑定：所有决策必须绑定至少一个搜索命中或上下文证据。
- 历史压缩：按阶段摘要与关键证据保留，过长时优先保留“决策+证据”对。

## 质量门控与指标（建议）
```yaml
closed_loop_quality_gates:
  search_latency:
    p95: 2000ms
    p99: 5000ms
  search_recall:
    baseline_min: 90%
  search_precision:
    false_positive_max: 5%
  cot_quality:
    step_has_evidence_min_ratio: 0.9
    step_has_decision_min_ratio: 0.9
  task_gen:
    tasks_max: 10
    dependency_resolution_success_min: 95%
  errors:
    error_rate_max: 2%
  resources:
    max_cpu_utilization: 85%
    max_memory_usage_mb: 1024
```

- 指标采集：
  - 搜索：`elapsedMs`、命中率与误报率、错误/取消/超时。
  - COT：步骤总数、含证据/决策的比率、压缩率、溢出警告次数。
  - 任务：生成任务数、依赖解析成功率、执行通过率与回退次数。
  - 资源：CPU/内存/IO；并发度与文件数。

## 异常处理与回退
- 输入歧义：低置信度触发澄清提示；建议限定范围或提供示例查询。
- 路径与权限：拒绝路径遍历；不可读目录记录并提示；替代路径建议。
- 大仓库与二进制：分片扫描与采样；二进制跳过；超大文件摘要式预览。
- 语义索引缺失：回退到正则/文本；异步构建嵌入索引与缓存。
- COT 溢出/漂移：压缩并重启阶段；强制证据绑定；必要时降级为直接任务模板。
- 任务冲突/循环依赖：检测并提示；自动分解或引导用户干预；回退到子任务执行。

## 安全与合规
- 输入安全：敏感词与命令过滤；危险操作强制审批与二次确认。
- 数据脱敏：搜索预览脱敏密钥/凭证；日志合规与最小留痕。
- 审计与复盘：记录输入、意图、搜索命中、COT 步骤、任务列表与执行结果，支持检索与复盘。

## 性能优化与工程实践
- 缓存：命中缓存与结果缓存；热目录与热门查询；COT 片段摘要缓存。
- 并发与分片：按目录/类型分片；IO 限流与优先级调度；流式批次输出。
- 索引：文件树/符号/嵌入索引增量构建；多语言 AST 感知。
- 去重与排序：行级/符号级去重；语义/位置/频次加权排序。
- 历史与模板：查询模板面板；重复查询聚合提示；任务模板复用。

## 落地步骤与检查清单
- 入口与意图：实现输入通道与意图识别；阈值与歧义澄清策略。
- 搜索与计划：打通多通道搜索与合并；默认配置与质量阈值。
- COT 与提示：阶段模板与约束提示；证据绑定与历史压缩。
- 任务与编排：结构化任务与工具合约；审批与取消；回退链与重试。
- 测试与门禁：在 `integration-tests/` 构造基准仓与查询集；CI 集成质量门禁。
- 遥测与面板：采集指标；在 CLI/IDE 增加“闭环度量面板与模板面板”。
