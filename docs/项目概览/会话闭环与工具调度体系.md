# 会话闭环与工具调度体系（系统化、结构化、分层次）

本文档从“多次工具调用、多次意图识别、思考”的完整闭环视角，系统化梳理核心节点与实现逻辑，覆盖聊天编排、工具调度、响应解析、确认与编辑器交互、错误与重试、度量与扩展方向，为二次开发提供清晰的架构脉络与可操作入口。

## 一、整体闭环
- 输入阶段：用户/系统指令、上下文历史、工具注册与提示控制
- 处理阶段：
  - 意图识别与消息验证
  - API 调用与流式响应处理
  - 工具调用调度与确认
  - 工具执行与结果合并
  - 状态与历史更新
- 输出阶段：用户可读展示、LLM 历史记录、遥测上报

## 二、核心模块与职责
- 会话编排：`packages/core/src/core/geminiChat.ts`
  - 历史抽取与压缩、请求拼装与日志、响应流处理与合并、最终用量统计与历史记录
- 工具调度：`packages/core/src/core/coreToolScheduler.ts`
  - 工具调用状态机（validating/awaiting_approval/scheduled/executing/success/error/cancelled）
  - 确认流程（生成 diff、用户选择、自动模式切换）
  - 编辑器交互修改（`modifyWithEditor`）与参数回写
  - 执行落盘与结果转换（`convertToFunctionResponse`）
- 非交互执行：`packages/core/src/core/nonInteractiveToolExecutor.ts`
  - 面向不可交互场景的工具执行封装，复用 `convertToFunctionResponse`
- 响应解析：`packages/core/src/utils/generateContentResponseUtilities.ts`
  - 文本提取、函数调用提取、结构化响应提取（from parts）
- MCP 集成：`packages/core/src/tools/mcp-tool.ts`
  - `callTool` 执行与 `getStringifiedResultForDisplay` 展示
- 工具抽象：`packages/core/src/tools/tools.ts`
  - `Tool`/`BaseTool` 定义、`ToolResult`、确认类型与选项
- 编辑器与修改：`packages/core/src/tools/modifiable-tool.ts` + `packages/core/src/utils/editor.ts`
  - 临时文件生成 → 外部编辑器 diff → 更新参数与 diff
- 纠错层：`packages/core/src/utils/editCorrector.ts`
  - 文本匹配与转义纠偏、LLM 介入修正、LRU 缓存

## 三、会话编排关键节点（GeminiChat）
- 输入合法性与内容过滤：`isValidResponse`、`isValidContent` 等初步验证
- 历史管理：`extractCuratedHistory` → `getHistory` → `recordHistory`
- 请求拼装：`_getRequestTextFromContents` + `_logApiRequest`
- 响应处理：`processStreamResponse`、`_logApiResponse`、`getFinalUsageMetadata`
- 思维内容标识：`isThoughtContent`（用于区分思考与输出）
- 重试与回退：在客户端与工具层统一使用指数退避 `retryWithBackoff`

## 四、工具调度与确认（CoreToolScheduler）
- 状态机：`setStatusInternal` 驱动各阶段转换，`notifyToolCallsUpdate` 通知变更
- 确认流转：
  - `shouldConfirmExecute` 返回 `ToolEditConfirmationDetails`（含 diff）
  - 用户选择：`ProceedOnce/ProceedAlways/ModifyWithEditor/Cancel`
  - `ProceedAlways` 切换到自动模式（`ApprovalMode.AUTO_EDIT`）
- 编辑器交互：
  - `isModifiableTool` → `getModifyContext` → `modifyWithEditor` → 更新参数与 diff
- 执行与合并：
  - 调度执行 `tool.execute`，将 `ToolResult.llmContent` 统一转为 `functionResponse`（`convertToFunctionResponse`）
  - CLI 展示使用 `ToolResult.returnDisplay`（通常为 diff 或字符串）
- 终止与完成：`cancelled/success/error` 终态，`checkAndNotifyCompletion` 触发遥测记录与回调

## 五、响应解析与意图识别
- 文本与函数调用提取：`getResponseTextFromParts`、`getFunctionCallsFromParts`
- 结构化结果提取：`getStructuredResponseFromParts`
- 函数响应识别：`messageInspectors.ts` 中的 `isFunctionResponse`（用于工具结果的识别与路由）

## 六、工具执行路径（以编辑/写入为例）
- 编辑替换：`EditTool`（`replace`）
  - 参数校验 → 读取文件 → `ensureCorrectEdit` 纠偏 → 生成 diff → 确认 → `_applyReplacement` → 写入 → 返回 llmContent 与 diff 展示
- 整文件写入：`WriteFileTool`（`write_file`）
  - 参数校验 → 读取文件 → `_getCorrectedFileContent`（存在则用 `ensureCorrectEdit`，不存在用 `ensureCorrectFileContent`）→ 生成 diff → 确认 → 写入 → 返回 llmContent 与 diff 展示 → 记录度量

## 七、错误与重试
- 参数与路径错误：绝对路径与根目录约束、目录写入拒绝
- 匹配失败与数量不符：`occurrences === 0` 或 `!== expected_replacements`
- 文件系统异常：读取失败（非 ENOENT）、权限问题、写入异常
- 编辑器异常：无法打开 diff 或工具不可用
- 重试策略：`packages/core/src/utils/retry.ts` 的 `retryWithBackoff`（延迟与 Retry-After）

## 八、度量与日志
- 工具调用日志：`logToolCall` 与 `ToolCallEvent`
- 写文件度量：`recordFileOperationMetric`（创建/更新、行数、MIME、扩展名）
- 请求/响应日志：`_logApiRequest`、`_logApiResponse`

## 九、二次开发扩展方向
- 意图识别增强：
  - 在 `GeminiChat` 中增加“意图分类器”模块，对工具触发条件进行可配置化（规则 + 模型）
  - 提供策略接口：基于消息内容、历史、模型信号动态决定是否触发工具
- 调度策略扩展：
  - 支持并行工具调度与冲突合并（基于调用依赖图）
  - 引入优先级队列与资源限流（同时控制 Approval 流程）
- 确认与编辑器 UX：
  - 在 `ToolEditConfirmationDetails` 中增加多视图（上下文预览、风险提示）
  - 扩展 `modifyWithEditor` 支持更多编辑器与双向同步（例如通过临时目录监听事件）
- 纠错层升级：
  - 针对多处匹配场景提供“选择范围”交互或半自动 disambiguation
  - 引入更强的结构化比较（AST/DOM 比对）以减少转义问题
- 遥测与回滚：
  - 写入操作生成恢复点（快照），失败或后悔时可回滚
  - 更精细的 KPI 采集与异常分类上报
- 安全与权限：
  - 针对 MCP/外部工具增加权限模型与安全沙箱
  - 在 CLI 展示层增加敏感操作提示与红线策略
