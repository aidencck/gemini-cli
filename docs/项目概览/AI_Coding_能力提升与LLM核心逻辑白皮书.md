# AI Coding 能力提升与 LLM 核心逻辑白皮书

面向技术负责人与架构师，系统梳理 AI Coding 如何提升编码能力，以及从 LLM 专家的视角，在哪些关键点进行提升与如何实施，提供度量指标与工程落地清单。
关键要点

- 能力维度
  - 任务规划与分解、上下文与记忆供给、工具调用编排、自我校验循环、多文件一致性、安全与可恢复性、性能与成本。
- 量化指标
  - 正确率（ pass@1 、测试通过率）、变更成功率、生成与审阅时长、缺陷率、风格一致性、上下文压力与压缩效果。
- LLM逻辑提升点
  - 规划-分解-依赖-验收、语义摘要与最近K轮混合、标准化函数调用与响应、自检循环、影子Git快照与审批、压缩与历史维护。
- 工程落地
  - 建立Repo Wiki与依赖图、准备高质量上下文池与提示模板库、接入工具编排与审批、自动快照与 /restore 回滚、集成测试与静态分析、指标看板。
- 案例与模板
  - 多文件重构、风险写入审批与快照、提示模板结构（目标/约束/文件表/接口契约/输出格式/验收）。
---

## 1. 目标与范围
- 目标：提升代码正确性、稳定性、安全性与交付速度，降低人工审阅与返工成本。
- 范围：任务规划、上下文管理、工具调用、代码生成与校验、质量保障、可恢复性与度量迭代。

---

## 2. 能力提升维度
- 任务规划与分解：将复杂需求拆解为原子任务，显式依赖管理与批次化执行。
- 上下文与记忆：高质量上下文供给（项目结构、接口契约、历史），语义压缩与有效保真。
- 工具调用（函数调用）：以标准 API/工具编排完成读写、搜索、生成、验证等动作。
- 代码生成质量：结构一致性、风格一致性、多文件关联一致性（跨文件引用/导入/测试）。
- 自我校验与反思：生成后执行单测/静态分析/自检规则，失败即迭代修正。
- 安全与可靠性：沙箱、最小权限、预览/确认、影子 Git 快照与可恢复性。
- 速度与成本：增量生成、缓存与复用、批处理回传减少往返。

---

## 3. 关键指标（可量化）
- 代码正确率：`pass@1`（一次生成通过率）、测试通过率（单测/集成）。
- 变更成功率：一次性合入成功占比、回滚率（越低越好）。
- 生成与审阅时间：平均生成时长、人工审阅时长、从生成到合入周期。
- 缺陷率：上线后缺陷数/严重度、静态分析告警数。
- 一致性：跨文件引用正确率、风格规范符合率。
- 上下文压力：接近 Token 上限的频次与覆盖策略效果（摘要保真度）。

---

## 4. LLM 核心逻辑（关键提升点）
- 规划与分解：明确“目标→子任务→依赖→验收准则”，以批次组织工具调用。
- 上下文工程：输入构造优先级（需求→接口→约束→代码片段→历史），语义摘要与最近 K 轮原文混合策略。
- 函数调用与工具编排：标准化 `ToolCallRequestInfo`、统一 `FunctionResponse` 回传，减少不一致。
- 自我校验循环：生成→静态分析→单测→失败快照→迭代修复（带异常原因）。
- 多文件一致性：建立 Repo Wiki/依赖图，在生成阶段显式校验导入、类型与接口契约。
- 可恢复性：在风险写入前自动快照（影子 Git），`awaiting_approval` → checkpoint JSON + commitHash。
- 交互审批：对高风险工具写入/替换采用审批模式，拒绝则终止并记录。
- 压缩与历史维护：接近上限时触发压缩事件，提示并采用摘要策略保障上下文连续性。

---

## 5. 如何具体提升（工程手段）
- 上下文供给体系：
  - 自动生成 Repo Wiki（模块说明、依赖图、常用接口）。
  - 维护可用上下文池：`README/接口契约/测试入口/配置`；优先级排序拼接到提示词。
- 提示工程模板：
  - 角色/目标/范围/约束/接口/文件表/风格规范/验收标准/输出格式（含 JSON/差异补丁）。
- 工具链集成：
  - 文件系统/搜索/多文件写入/MCP 工具；统一状态机与批次事件回传。
- 质量保障：
  - 生成后自动运行单测与静态分析；规范化报错格式用于下一轮修复提示。
- 安全与隔离：
  - 沙箱、只读默认、写入需审批；影子 Git 快照 + `/restore` 一键回滚。
- 性能优化：
  - 增量生成与差异补丁；常用路径与接口缓存；批次提交减少往返。
- 度量与迭代：
  - 采集生成-审阅-合入全链路指标；对低 `pass@1` 的场景做专项模板与上下文优化。

---

## 6. 落地实施清单（可执行）
- 建立 Repo Wiki 与依赖图；准备高质量上下文池与优先级规则。
- 制定提示模板库与任务分解 SOP。
- 接入工具编排与审批模式；配置高风险工具写入需确认。
- 启用影子 Git 快照；在 `awaiting_approval` 自动创建 checkpoint。
- 集成单测与静态分析到生成后自检；失败信息进入迭代循环。
- 建立度量看板：正确率、变更成功率、审阅时长、缺陷率、压缩事件频次。

---

## 7. 场景案例与模板
- 多文件重构：
  - 规划子任务 → 读取依赖图 → 生成补丁 → 运行单测 → 审批写入 → 快照合入。
- 高风险写入工具：
  - `awaiting_approval` 触发快照与 checkpoint JSON；拒绝则终止并保留审计。
- 提示模板片段：
  - 目标与约束 + 文件表 + 接口契约 + 输出格式（`diff`/`patch`/`json`） + 验收。

---

## 8. 接入建议与路径
- 在 CLI/IDE 引入“任务列表面板”，映射 `TrackedToolCall` 到统一 Task 模型与优先级。
- 为写入/替换类工具默认开启审批与快照；为查询类工具走非交互直通道。
- 对失败率高的任务场景建立专项模板与上下文增强策略。

---

## 9. 结论
通过规划分解、上下文工程、工具编排与自我校验循环，再配合快照与审批、安全隔离与度量反馈，AI Coding 能在真实工程中稳定提升代码正确性、交付效率与可恢复性，实现面向生产的端到端闭环。
