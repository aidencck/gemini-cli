# 项目架构深度综述（模型认知与版本适配专篇）

面向产品专家、技术专家、架构师与 LLM 专家，系统梳理「LLM 如何在思维链与推理过程中理解与使用项目全量信息」「当组件/信息/源代码变更时如何自适应与治理」，并给出可落地的工程步骤与改动清单。

## 一、执行摘要（Executive Summary）
- 全景目标：保障多回合智能协作在项目变更下的稳定性、可重入与低成本。
- 认知路径：系统提示 + 精选历史 + RAG/检索 + 工具响应 + 代码生成产物索引的多源融合，统一结构化装配与 COT 隔离。
- 关键机制：意图判定、函数/工具闭环、输出契约、历史压缩与重置、观测与治理（延迟/成本/错误率）。
- 版本自适应：通过“变更监听 → 索引刷新 → 提示/策略更新 → 契约校验 → 回归与灰度”闭环管理，最小化对话破坏与认知漂移。

## 二、全景目标与范围
- 覆盖 CLI/IDE 会话、工具调度、输出装配、历史维护、模型适配与可观察性。
- 面向“源代码与文档持续变更”的工程场景，提供分层策略与改动点清单。
- 保持跨端一致消费（文本 + JSON/工具响应），确保时序一致与幂等。

## 三、模型认知与信息供给（信息入口与结构化契约）
- 信息入口：
  - 系统提示与会话上下文：注入项目概览、目录结构与关键约束（安全、隐私、成本）。
  - 精选历史（用于判定与续写）：仅保留关键轮次与结构化片段，避免冗余与污染。
  - RAG/检索：从代码与文档检索片段（文件/段落/接口），以引用形式供模型推理。
  - 工具响应：统一 functionResponse（文本/文件/二进制 → 标准 JSON），可复用与可审计。
  - 代码生成产物索引：新增/修改文件路径、摘要与变更原因，供后续推理与决策。
- 结构化契约：
  - 输出合并：文本 + 函数调用 + 工具响应统一装配，保证跨端一致消费。
  - COT 隔离：`thought: true` 段在运行时侧隔离（不回放），仅用于内部推理与评估。
  - 非法结构兜底：空 `parts` 注入空文本、缺失字段补齐、函数响应一致性校验。

## 四、工程关键识别逻辑（分层能力）
- 意图判定与下一说话人：根据精选历史与门控策略（规则/概率/成本），决定模型续写与工具路径。
- 函数调用识别：解析模型输出的 `functionCall`，进行参数校验、许可检查与幂等执行。
- COT 识别与过滤：探测思维链片段并隔离，避免泄露与不一致重放。
- 工具调度闭环：验证 → 调度 → 执行 → 成功/失败/取消 → 结果转译 → 历史写入 → 续写。
- 输出装配：将文本与工具结果合并为“可消费对象”（CLI/文档/API），保持非/流式一致路径。
- 历史维护：综合历史 + 精选历史双轨；阈值压缩、摘要、重置与非法结构修复。
- 模型适配：选择与参数（温度/Top-p/最大令牌/流式），重试与回退策略，路由/并发节流。
- 观测与治理：指标（延迟/成本/错误率）、日志、权限与隐私、审计与灰度策略。

## 五、LLM 在思维链推理中的项目全量认知路径
- 代码与文档理解：
  - 目录与关键文件提示（概览、组件、入口、脚本、配置）。
  - 变更摘要与索引（新增/修改/删除清单、理由与影响范围）。
  - 关键契约引用（API、工具协议、输出格式），避免记忆幻觉。
- 生成产物识别：
  - 写入后的文件路径与摘要自动入库（索引刷新），供后续回合引用。
  - 工具/脚本输出的结构化记录，形成事实基座（可复查与审计）。

## 六、版本迭代与内部自适应策略（变更驱动的闭环）
- 变更来源：组件与接口、工具注册与参数、配置与策略、提示模板与输出契约、数据与依赖。
- 调整动作：
  - 提示模板更新：注入最新目录/接口/策略开关；兼容旧版与回退路径。
  - 策略参数更新：判定阈值、压缩/摘要、并发与节流；场景化切换（本地优先/模型优先）。
  - 工具协议更新：注册/权限/参数校验；统一响应转译；失败与取消路径。
  - 输出契约更新：字段新增/变更的契约测试与快照校验；跨端消费者同步。
  - 历史迁移与重置：在阈值/变更事件下重建精选历史，保障判定质量。
  - 测试与灰度：单测/集成/契约测试 + 分阶段上线与回滚策略。
- 自动化流程：
  - 变更监听：代码/配置/协议文件的 Hook 与差异报告（新增/修改/删除）。
  - 索引刷新：生成目录与文件摘要索引（路径/要点/契约引用）。
  - 契约校验：输出格式与工具响应的快照比对，防止消费者破坏。
  - 回归测试：针对核心分支（判定/调度/装配/压缩）运行最小必要用例。
  - 观测与告警：延迟/错误率/成本的阈值检测与告警；自动降级与重试。

## 七、LLM 改动点清单（运行时与策略层）
- 运行时侧：提示模板、路由策略、并发/节流、重试/回退、流式开关。
- 解析侧：函数调用抽取、工具响应转译、非法结构兜底、COT 探测与隔离。
- 历史侧：精选/综合维护、压缩阈值、摘要策略、重置条件与恢复流程。
- 契约侧：输出合并格式、字段版本化、快照与兼容适配层。
- 工具侧：注册/权限模型、参数校验、失败/取消状态、审计与安全策略。
- 观测侧：指标字典（延迟/成本/错误率/压缩频率/工具成功率）、日志级别与追踪 ID。

## 八、工程落地步骤（可操作清单）
1) 建立项目索引与摘要生成脚本：
   - 扫描 `packages/*`、`scripts/*`、`docs/*`，生成“路径+要点+契约引用”的 JSON 索引。
   - 变更触发时增量刷新；会话编排在提示中注入索引摘要。
2) 强化会话编排提示模板：
   - 固定段：项目概览、目录要点、工具协议、输出契约、隐私与成本约束。
   - 动态段：最新变更摘要、核心文件片段、待办与风险提示。
3) 输出契约与快照测试：
   - 定义“文本+JSON/工具响应”的统一结构；添加契约/快照测试与破坏报警。
4) 版本变更流水线：
   - 监听 → 索引刷新 → 契约校验 → 最小回归 → 灰度上线 → 观测告警。
5) 观测面板与告警：
   - 指标：延迟、成本、错误率、工具成功率、压缩频率；
   - 告警：超阈值自动降级（本地优先/减少并发/关闭非核心工具）。

## 九、质量度量与可观察性
- 指标体系：
  - 生成侧：命中率（意图/函数）、COT 过滤正确率、输出装配错误率。
  - 工具侧：成功率、超时率、重试次数、取消/失败分布。
  - 历史侧：压缩频率、精选命中率、重置次数与恢复耗时。
  - 成本侧：令牌用量、并发与等待、费用估算与趋势。
- 日志与追踪：
  - 关键节点打点（解析/调度/装配/写入/判定）；
  - 关联 ID（会话/工具/文件/版本），支持根因定位与审计。

## 十、治理与合规
- 最小披露与脱敏：提示与工具参数/返回值脱敏；
- 权限与审计：敏感操作确认、白名单、审计链与留痕；
- 区域化与数据主权：按部署域进行隔离与合规审查。

## 十一、路线图（分阶段演进）
- P0：索引与提示增强、契约与快照测试、关键指标与告警落地。
- P1：策略引擎（意图/成本/概率门控）、RAG 引入与知识增强、工具协议可视化。
- P2：企业级治理（SLA、细粒度权限、合规）、持久化会话与恢复、控制台与时序图。
