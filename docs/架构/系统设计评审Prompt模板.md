# 系统设计评审Prompt模板

## 概述
本模板用于对系统设计进行全面的技术评审，从多个维度评估设计的合理性、可行性和风险。

## 使用场景
- 系统架构设计评审
- 技术方案可行性评估
- 项目风险评估
- 技术选型决策支持
- 设计质量保证

## Prompt模板

```
# 系统设计评审Prompt

请对以下系统设计进行全面的技术评审：

## 评审维度

### 1. 架构设计评审
- 评估架构的合理性和完整性
- 分析设计模式和架构原则的应用
- 评估系统的可扩展性和可维护性

### 2. 技术选型评审
- 评估技术栈的适用性和成熟度
- 分析技术选型的风险和成本
- 评估技术生态和社区支持

### 3. 性能设计评审
- 评估性能设计方案的合理性
- 分析性能瓶颈和优化策略
- 评估容量规划和扩展能力

### 4. 安全设计评审
- 评估安全架构的完整性
- 分析安全风险和防护措施
- 评估合规性和审计要求

### 5. 可用性设计评审
- 评估系统的可用性和可靠性
- 分析故障恢复和容错机制
- 评估监控和运维支持

### 6. 成本效益评审
- 评估开发和运维成本
- 分析投资回报和商业价值
- 评估技术债务和长期维护

## 输出要求

请提供：
1. 设计优点和亮点总结
2. 设计问题和风险分析
3. 改进建议和优化方案
4. 技术债务评估
5. 实施建议和优先级排序
6. 后续跟踪和验证计划

## 设计文档
[在此处粘贴系统设计文档]
```

## 评审维度详解

### 1. 架构设计评审
**目标**: 评估系统架构的设计质量和合理性
**关注点**:
- **架构完整性**: 是否覆盖了所有业务需求
- **架构合理性**: 是否符合软件工程原则
- **设计模式**: 设计模式的应用是否恰当
- **可扩展性**: 是否支持未来功能扩展
- **可维护性**: 是否便于长期维护和演进

**评审标准**:
- 架构层次是否清晰
- 组件职责是否明确
- 依赖关系是否合理
- 扩展点是否充分
- 技术债务是否可控

### 2. 技术选型评审
**目标**: 评估技术栈选择的合理性和风险
**关注点**:
- **技术成熟度**: 技术的稳定性和可靠性
- **团队能力**: 团队对技术的掌握程度
- **生态支持**: 社区活跃度和第三方支持
- **学习成本**: 新技术的学习和培训成本
- **长期维护**: 技术的长期支持和更新

**评审标准**:
- 技术是否满足业务需求
- 团队是否有相关经验
- 社区支持是否充分
- 学习成本是否可接受
- 长期维护是否可持续

### 3. 性能设计评审
**目标**: 评估系统性能设计的合理性
**关注点**:
- **性能指标**: 响应时间、吞吐量、并发能力
- **性能瓶颈**: 潜在的性能瓶颈点
- **优化策略**: 性能优化的方法和措施
- **容量规划**: 系统容量和扩展规划
- **监控体系**: 性能监控和告警机制

**评审标准**:
- 性能指标是否明确
- 瓶颈分析是否充分
- 优化策略是否可行
- 容量规划是否合理
- 监控体系是否完善

### 4. 安全设计评审
**目标**: 评估系统安全设计的完整性
**关注点**:
- **安全威胁**: 潜在的安全威胁和风险
- **防护措施**: 安全防护的技术措施
- **认证授权**: 用户认证和权限控制
- **数据安全**: 数据加密和隐私保护
- **合规要求**: 行业合规和法规要求

**评审标准**:
- 威胁分析是否全面
- 防护措施是否有效
- 认证授权是否完善
- 数据安全是否保障
- 合规要求是否满足

### 5. 可用性设计评审
**目标**: 评估系统的可用性和可靠性
**关注点**:
- **可用性指标**: 系统可用性和SLA要求
- **故障恢复**: 故障检测和恢复机制
- **容错设计**: 容错和降级策略
- **监控运维**: 系统监控和运维支持
- **灾难恢复**: 灾难恢复和备份策略

**评审标准**:
- 可用性指标是否明确
- 故障恢复是否及时
- 容错设计是否充分
- 监控运维是否完善
- 灾难恢复是否可行

### 6. 成本效益评审
**目标**: 评估项目的成本效益和商业价值
**关注点**:
- **开发成本**: 人力、时间、工具成本
- **运维成本**: 基础设施、维护、升级成本
- **投资回报**: 项目收益和ROI分析
- **技术债务**: 技术债务的积累和影响
- **长期价值**: 系统的长期商业价值

**评审标准**:
- 成本估算是否准确
- 收益分析是否合理
- 投资回报是否可接受
- 技术债务是否可控
- 长期价值是否明确

## 评审方法

### 1. 文档审查
**方法**: 详细审查设计文档和规范
**重点**:
- 文档的完整性和准确性
- 设计的一致性和合理性
- 规范的遵循程度
- 细节的考虑程度

### 2. 技术调研
**方法**: 调研相关技术和最佳实践
**重点**:
- 技术的成熟度和稳定性
- 社区支持和生态情况
- 成功案例和失败教训
- 发展趋势和前景

### 3. 专家咨询
**方法**: 咨询相关领域专家
**重点**:
- 专家的专业意见
- 行业最佳实践
- 潜在风险和问题
- 改进建议和方案

### 4. 原型验证
**方法**: 通过原型验证设计可行性
**重点**:
- 技术方案的可行性
- 性能指标的达成
- 用户体验的验证
- 风险的早期识别

## 输出格式建议

### 1. 评审总结报告
```markdown
## 设计评审总结

### 设计优点
- [ ] 架构设计清晰，层次分明
- [ ] 技术选型合理，团队熟悉
- [ ] 性能设计充分，优化策略明确
- [ ] 安全设计完善，防护措施到位

### 设计问题
- [ ] 扩展性考虑不足，可能影响未来扩展
- [ ] 技术债务风险较高，需要关注
- [ ] 监控体系不够完善，运维支持不足
- [ ] 成本估算偏低，可能超出预算

### 风险评估
- **高风险**: 技术债务积累，长期维护困难
- **中风险**: 扩展性限制，功能扩展受限
- **低风险**: 监控不足，问题排查困难
```

### 2. 改进建议
```markdown
## 改进建议

### 高优先级
1. **架构优化**: 重新设计扩展机制，提高系统扩展性
2. **技术债务管理**: 制定技术债务偿还计划，控制债务积累
3. **监控体系完善**: 建立完善的监控和告警体系

### 中优先级
1. **性能优化**: 优化关键路径，提高系统性能
2. **安全加固**: 加强安全防护，提高系统安全性
3. **文档完善**: 补充设计文档，提高可维护性

### 低优先级
1. **工具优化**: 优化开发工具，提高开发效率
2. **流程改进**: 改进开发流程，提高交付质量
```

### 3. 实施计划
```markdown
## 实施计划

### 第一阶段：风险控制（1-2周）
- [ ] 技术债务评估和偿还计划
- [ ] 监控体系设计和实施
- [ ] 安全漏洞修复和加固

### 第二阶段：架构优化（2-3周）
- [ ] 扩展机制重新设计
- [ ] 性能瓶颈优化
- [ ] 容错机制完善

### 第三阶段：质量提升（1-2周）
- [ ] 文档完善和规范
- [ ] 测试体系优化
- [ ] 部署流程改进
```

## 评审工具和方法

### 1. 架构评估工具
- **架构评估矩阵**: 多维度评估架构质量
- **依赖关系图**: 分析组件依赖和耦合
- **复杂度分析**: 评估系统复杂度
- **可扩展性评估**: 分析扩展能力和限制

### 2. 风险评估方法
- **风险矩阵**: 评估风险的可能性和影响
- **故障树分析**: 分析系统故障原因
- **影响分析**: 评估变更对系统的影响
- **成本效益分析**: 评估投资回报和风险

### 3. 质量评估指标
- **代码质量**: 复杂度、重复度、覆盖率
- **性能指标**: 响应时间、吞吐量、资源使用
- **安全指标**: 漏洞数量、安全等级、合规程度
- **可用性指标**: 可用性、可靠性、可维护性

## 评审流程

### 1. 准备阶段
- 收集设计文档和相关信息
- 确定评审团队和专家
- 制定评审计划和议程
- 准备评审工具和模板

### 2. 评审阶段
- 进行文档审查和技术调研
- 组织专家评审和讨论
- 识别问题和风险点
- 提出改进建议和方案

### 3. 总结阶段
- 整理评审结果和建议
- 制定实施计划和优先级
- 建立跟踪和验证机制
- 更新设计文档和规范

### 4. 跟踪阶段
- 跟踪改进措施的实施
- 验证改进效果和成果
- 更新风险评估和计划
- 持续优化和改进

## 最佳实践

### 1. 评审原则
- **客观公正**: 基于事实和数据进行分析
- **全面深入**: 从多个维度进行全面评估
- **实用可行**: 建议要实用可行，便于实施
- **持续改进**: 将评审作为持续改进的过程

### 2. 评审技巧
- **重点关注**: 根据项目特点确定重点
- **对比分析**: 与同类项目或最佳实践对比
- **专家咨询**: 充分利用专家经验和知识
- **原型验证**: 通过原型验证设计可行性

### 3. 团队协作
- **充分沟通**: 与团队充分沟通评审结果
- **知识分享**: 分享评审经验和最佳实践
- **培训支持**: 提供必要的培训和指导
- **持续支持**: 提供持续的技术支持

## 使用技巧

1. **准备充分**: 在评审前充分准备相关文档和信息

2. **团队协作**: 组织合适的评审团队，包括相关专家

3. **客观分析**: 基于客观事实进行分析，避免主观偏见

4. **实用建议**: 提供实用可行的改进建议

5. **持续跟踪**: 建立持续跟踪机制，确保改进措施落实

## 常见问题

### Q: 如何确定评审的重点？
A: 评审重点确定方法：
- 根据项目阶段和特点确定重点
- 关注高风险和高影响的问题
- 结合业务需求和技术约束
- 参考行业最佳实践和标准

### Q: 评审结果如何应用？
A: 评审结果应用方法：
- 指导后续的设计和开发工作
- 制定改进计划和实施策略
- 作为技术决策和选型的依据
- 用于团队培训和知识分享

### Q: 如何保证评审的质量？
A: 保证评审质量的方法：
- 组织合适的评审团队和专家
- 使用科学的评审方法和工具
- 建立完善的评审流程和标准
- 进行充分的准备和调研
